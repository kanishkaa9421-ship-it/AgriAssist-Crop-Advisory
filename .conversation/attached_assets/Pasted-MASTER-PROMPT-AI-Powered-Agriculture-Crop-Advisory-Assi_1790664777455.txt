2. Core Mission Directive
Develop a comprehensive "AI-Powered Agriculture Crop Advisory Assistant." This platform must serve as a smart, accessible companion for farmers, helping them mitigate risks associated with crop diseases, unpredictable weather patterns, and fluctuating market prices. The application must bridge the gap between complex agricultural science and actionable daily farming practices.

3. Product Goal
To provide farmers with instant, hyper-personalized, AI-generated crop advisory. By inputting specific crop details, environmental conditions, and visible symptoms (via text), the system will output precise disease diagnoses, weather impact mitigation strategies, and market trend awareness, ultimately reducing crop loss and increasing yield predictability.

4. Mandatory Features
Crop Portfolio Management: Users can log and track their current active crops, planting dates, and acreage.

AI Disease Diagnosis & Treatment: Users can input symptoms and receive step-by-step treatment plans, chemical/organic recommendations, and prevention strategies.

Weather Risk Mitigation: Provide actionable advice on how to protect specific crops based on current or upcoming adverse weather conditions.

Market Intelligence Insights: AI-generated estimations on harvest timing to maximize market prices based on historical trends and crop maturity.

Advisory History Logging: Every AI consultation must be saved for future reference and continuity of care.

AI Integration: @google/genai SDK (Strictly use the official Google Gen AI SDK).

6. Application Pages (Routes)
/ - Dashboard: Overview of user's active crops, recent advisory logs, and quick actions.

/crops - Crop Management: Add, edit, or remove active crops from the user's farm profile.

/advisory/new - New Advisory Request: The core form where users request AI help (Disease, Weather, or Market query).

/advisory/:id - Advisory Result: Detailed view of a specific AI consultation and action plan.

/history - Advisory Log: Chronological list of all past advice and diagnoses.

7. User Flow
User lands on the Dashboard and navigates to the Crop Management page to register a new crop (e.g., "Tomato - Roma", planted 30 days ago).

User notices yellowing leaves and navigates to "New Advisory Request."

User selects the affected crop from a dropdown, selects the query type ("Disease/Pest"), and describes the symptoms in a text area.

The frontend sends this payload to the backend Express server.

The backend validates the request with Zod, constructs a secure prompt, and calls the Gemini API via @google/genai.

Gemini processes the query and returns structured JSON conforming to a strict schema.

The backend saves the query and AI response to the Replit Postgres database.

The frontend routes the user to the "Advisory Result" page, rendering the structured JSON data into readable, color-coded action items.

10. Database Schema (Production SQL for PostgreSQL)
Execute this schema exactly as written to set up the Replit Postgres database:

SQL
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE crops (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    crop_name VARCHAR(100) NOT NULL,
    crop_category VARCHAR(50) NOT NULL,
    planting_date DATE NOT NULL,
    acreage DECIMAL(10, 2),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE advisory_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    crop_id UUID REFERENCES crops(id) ON DELETE CASCADE,
    advisory_type VARCHAR(50) NOT NULL,
    symptoms_description TEXT,
    ai_response JSONB NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
11. Row Level Security (RLS) / Data Isolation Rules
Ensure all database queries in the Node.js backend strictly filter by user_id.

A user must not be able to fetch, update, or delete crops or advisory_logs belonging to another user.

Implement middleware in Express that extracts the user_id (for this MVP, use a mock user ID passed in headers, e.g., x-user-id: <uuid>) and injects it into the request context for database operations.

12. Backend API Routes
Implement the following RESTful endpoints in Express:

GET /api/crops - Fetch all crops for the authenticated user.

POST /api/crops - Add a new crop.

16. Zod Validation Requirements
Use this exact Zod schema for both validating the backend API response and defining the Gemini responseSchema:

JavaScript
import { z } from "zod";

export const advisoryResponseSchema = z.object({
  primary_diagnosis: z.string().describe("The most likely issue or disease affecting the crop."),
  confidence_level: z.enum(["High", "Medium", "Low"]).describe("Confidence level in the diagnosis based on symptoms."),
  immediate_actions: z.array(z.string()).describe("1-3 critical steps the farmer must take in the next 24 hours."),
  treatment_plan: z.array(z.object({
    step_number: z.number(),
    description: z.string(),
    type: z.enum(["Organic", "Chemical", "Cultural", "Market"])
  })).describe("Step-by-step resolution plan."),
  preventative_measures: z.array(z.string()).describe("How to prevent this in the future or next season.")
});
Instruct the Gemini SDK to return data matching this schema by utilizing the structured outputs feature of the @google/genai SDK.
